### Стыковка с генерацией видео — половина VibePost готова (23 июля)

Это то самое, ради чего затевалась взаимоувязка. **Приёмная сторона построена, задеплоена и проверена.**

Идея: внешний конвейер генерирует короткие вертикальные ролики (Veo) → «сдаёт» их в VibePost → ролики ждут решения в разделе «Входящие ролики» → Татьяна смотрит, выбирает канал и время → дальше публикует обычный планировщик.

**Что сделано:**
- Таблица `incoming_videos` (id, name, prompt, source, caption, video_url, status `new`/`scheduled`/`dismissed`) + RLS
- Edge Function **`ingest-video`** — приёмник: multipart-загрузка, защита секретным заголовком, файл в бакет `post-photos`, запись в таблицу
- Секрет и `user_id` владельца лежат в Vault — конвейеру знать владельца не нужно
- Скрипт перенастройки `scripts/setup-ingest.mjs`
- **Проверено вживую:** чужой запрос отбит (403), правильный — принял файл и метаданные, вернул `{ id, video_url }`, запись создалась; тестовые данные убраны

**Контракт для команды конвейера:**

```
POST https://rjtyjybwygfkdekdzqbm.supabase.co/functions/v1/ingest-video
Content-Type: multipart/form-data
Заголовок:  X-Ingest-Secret: <секрет>

Поля тела:
  file    — видеофайл (обязательно)
  name    — название ролика
  prompt  — промпт, которым генерили
  source  — метка источника, напр. veo-pipeline
  caption — предлагаемая подпись к посту

Ответы: 200 { id, video_url } — принято
        403 — неверный секрет
        400 — нет файла
```

Секрет лежит в файле `.env` под именем `INGEST_SECRET` (открыть Блокнотом, скопировать, передать команде конвейера). Никакой ключ Supabase конвейеру не нужен — только адрес и этот секрет.

## 2. Где мы остановились

**Последний разговор — 26 июля, 19:23 МСК.** Татьяна прислала ссылку на https://aistudio.google.com/apikey и спросила: есть ли у неё ключ и можно ли им отправлять сгенерированные видео в постинг.

Ответ был такой:
- ключ сам по себе пост не публикует — он «пропуск» к Google для генерации видео моделью Veo;
- **приёмная половина у нас уже есть** (`ingest-video`), не хватает **генерирующей половины** — мостика «промпт → Veo → ingest-video»;
- генерация Veo платная, нужен включённый биллинг в Google.

И был задан вопрос с двумя вариантами — **на него Татьяна не ответила, на этом чат оборвался**:

1. Собрать мостик «промпт → Veo → ingest-video» на её стороне (нужен API-ключ в `.env` и биллинг у Google), либо
2. Сначала живой тест: сгенерировать пробный ролик через доступный генератор и прогнать через `ingest-video`, чтобы увидеть весь путь целиком.

**Это открытая точка входа в работу. С неё и продолжаем.**

## Известные ограничения (не баги, чинить не нужно)

- **Просмотры постов канала боту недоступны** — в аналитике всегда 0. Ограничение Telegram Bot API.
- **Реакции приходят с задержкой 1–5 минут** и только если бот — админ канала.
- **Видео с автопроигрыванием не крутится в Telegram Web** — у клиента отключён автоплей GIF в настройках. На телефоне работает.
- **Логи Edge Functions отстают ~20 минут.**
