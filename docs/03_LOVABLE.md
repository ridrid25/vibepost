# Промпты для Lovable

## Общий контекст (вставлять первым сообщением в Lovable)

```
Приложение VibePost — отложенный постинг в Telegram. Бэкенд уже готов и живёт в Supabase
(таблицы, RLS, Edge Functions) — его НЕ трогать и НЕ пересоздавать: только читать/писать
данные через @supabase/supabase-js и вызывать существующие Edge Functions через
supabase.functions.invoke().

Стек: React 18 + TypeScript, Tailwind CSS, shadcn/ui, TanStack Query, react-hook-form + zod.
Язык интерфейса — русский. Часовой пояс отображения — Москва (МСК); в БД время хранится
в UTC, при сохранении конвертировать МСК → UTC, при показе — обратно.
Стиль: воздушный, светлый; основной цвет #3B82F6, фон #F8FAFC.

Навигация (сайдбар): Все посты / Шаблоны / Цепочки / Аналитика / Настройки.
Авторизация: Supabase Auth (email/пароль), страницы входа и регистрации, защищённые роуты.
```

## Страница «Все посты»

```
Сделай страницу «Все посты»: сверху переключатель Календарь/Список, фильтр «Все чаты»
(select из таблицы chats), кнопка «Новый пост». Календарь по месяцам, в ячейках дней —
компактные превью постов (время МСК + первые слова). Список — карточки с статусами:
Запланирован (синий), Отправлен (зелёный), Ошибка (красный). Данные из таблицы posts
текущего пользователя, сортировка по scheduled_at.
```

## Модалка «Новый пост»

```
Модалка создания поста: выбор бота (bots) и чата (chats этого бота); переключатель формата
Текст/Фото/Опрос. Для текста — textarea; для фото — загрузка в Supabase Storage (bucket
post-photos) + подпись; для опроса — поле «Вопрос опроса», динамический список «Варианты
ответов» (кнопка «Добавить вариант», минимум 2), чекбокс «Анонимное голосование».
Секция «Инлайн-кнопки»: пары текст+URL, кнопка «Добавить». Чекбоксы «Тихая отправка» и
«Отключить превью ссылок». Поля «Дата» и «Время (МСК)». Кнопка «Запланировать» — insert
в posts со status='scheduled' и scheduled_at в UTC. Валидация через zod.
```

## Страница «Цепочки»

```
Страница «Цепочки», два блока.
1) «Активные цепочки»: карточки — название, бот, чат, статус (running/paused/done),
прогресс «X/Y шагов» (по active_chain_steps со status='sent'), кнопки Пауза/Возобновить —
вызывают Edge Function toggle-chain (invoke с { active_chain_id, action: 'pause'|'resume' }).
2) «Шаблоны цепочек»: список message_chains с числом шагов и суммарной длительностью;
редактор шагов (позиция, задержка в минутах, контент или шаблон); кнопка «Запуск» открывает
выбор бота и чата и вызывает Edge Function activate-chain ({ chain_id, bot_id, chat_id }).
```

## Страница «Настройки»

```
Страница «Настройки», три секции.
1) «Telegram Боты»: форма (Токен бота — password-поле, Название) + кнопка «Добавить бота» →
invoke Edge Function validate-bot ({ token, name }); список ботов (имя, @username, число
чатов) с кнопкой удаления. Внутри бота — привязка чата: поле Chat ID + кнопка → invoke

Токен после добавления нигде не показывать.
2) «Уведомления об ошибках»: поле Telegram ID, select бота-отправителя, кнопка «Сохранить» —

3) «Статистика»: карточки — всего постов, отправлено, ошибок (count по posts).
```

## Экран «Входящие»: спрашивать название, а не подпись (04.08.2026)

Причина: заголовок в кадре вжигается на компьютере из поля `name` — из части
после тире. Приложение же спрашивает только подпись к посту, а её мы под
видео вообще не ставим. Ролики выходили без заголовка.

```
Страница «Входящие» (таблица incoming_videos). Бэкенд уже есть, таблицы и
Edge Functions не создавай — работай с существующими полями.

Убрать: выбор подписи к посту из пяти вариантов (поля caption и
caption_options). Подписи под видео-постами мы не ставим, этот шаг лишний.
Сами поля в базе не удаляй, просто не показывай.

Добавить в карточку ролика поле «Название» (поле name, одна строка):
- формат «Герой — ЗАГОЛОВОК», пример-подсказка в placeholder:
  «Скат — НА ДНЕ УЮТНЕЕ, ЧЕМ В ДОЛГАХ»
- подпись под полем: «Что после тире — станет заголовком в кадре»
- сохранение по кнопке с галочкой, update incoming_videos set name

Пока в названии нет тире:
- кнопки «Согласовать» и «В расписание» неактивны
- рядом строка серым: «Без названия заголовок в кадр не поставить»

Поле ready ставить в true при сохранении названия с тире (раньше оно
ставилось при выборе подписи — эту связь убрать).

Показать в карточке замер, если measure_avg не пустое:
- «Динамика N (норма 18)», «Худшая секунда N (норма 9)», «Склеек N»
- число ниже нормы — красным, в норме — обычным

Кнопку «↩︎ На доделку» оставить как есть: пишет rework_note и
status = 'rework'. После нажатия показать «Замечание отправлено».

Поля polished_at, video_url, measure_* приложение не меняет — их пишет
приёмник на компьютере.

Вёрстка: мобильная главная. Действия — иконками в один ряд, без подписей и
выпадающих меню, ничего не накладывается. Проверить на ширине 360 px.
```

## Правила для всех промптов

- Отдавать Lovable по одной странице за раз, проверять, потом следующую.
- Если Lovable предлагает «создать таблицы» или «написать Edge Function» — отвечать «нет,
  бэкенд уже существует, используй существующие».
- Точные имена функций и примеры invoke Claude Code выдаёт после каждого этапа — подставлять
  их в промпты при необходимости.

## Промпт: свежие ролики наверху

`incoming_videos.last_activity_at` — вычисляемое поле, максимум из
`created_at`, `polished_at`, `rework_at`, `rework_ack_at`. База считает его
сама, писать в него нельзя.

Во «Входящих» сортировать по нему, а не по `created_at`:

```
.order('last_activity_at', { ascending: false })
```

Смысл: ролик, у которого сменили заголовок или отправили на переделку, должен
всплыть наверх. Раньше он оставался внизу среди сорока других, и Татьяна
искала его глазами.

Во «Входящих» показывать сохранённое назначение ролика
`target_platform = youtube_shorts` как `YouTube Shorts`. Это назначение, а не
доказательство автоматической публикации. Пока YouTube provider отсутствует,
UI не должен обещать автозагрузку: финальная публикация выполняется владельцем
вручную. Технические Reference DNA/VPH/формулы в owner UI не выводить.

## Дайджест новостей: новые статусы и id сообщения (09.09)

В таблице `news_digests` появились поля `tg_message_id` (bigint), `last_error`
(text) и `post_id` (uuid → `posts.id`). Список статусов расширен, старый набор
из трёх значений больше не полный:

- `draft` — «ждёт решения»
- `queued` — «в очереди» (решение принято, пост стоит на 09:30 МСК)
- `posted` — «опубликован» (только с непустым `tg_message_id`)
- `skipped` — «пропущен»
- `failed` — «сбой», причину показывать из `last_error` мелким текстом под строкой

Где сейчас рисуется «опубликован» по `status='posted'` — оставить как есть, но
добавить два новых значения, иначе `queued` и `failed` покажутся пустыми.

Проверка доставки: дайджест реально дошёл до канала тогда и только тогда, когда
`tg_message_id is not null`. Статус без id — это ещё не публикация.
