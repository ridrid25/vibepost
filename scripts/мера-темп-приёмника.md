# Мера: темп приёмника после оплаты (НЕ ПРИМЕНЕНА)

Смена 93, 05.10.2026 04:05 МСК. Готово к применению, ждёт слова заказчицы.
Применять **после** перехода на Pro, а не сейчас: под 402 приёмник и так
отбивается на первом запросе.

## Что лечим

`scripts/watch-videos.mjs:38` — `const POLL_MS = 5000;` и
`scripts/watch-videos.mjs:1376` — `setInterval(tick, POLL_MS);`

Один тик зовёт одиннадцать подпрограмм (строки 1356-1369). Замерено по
управляющему API (`analytics/endpoints/usage.api-counts`, живёт под 402):

| сутки | запросов к REST | что было |
|---|---|---|
| 26.09 | 5 601 | приёмник ещё не запущен |
| 27.09 | 157 996 | приёмник запущен |
| 28.09 | 147 250 | он же |
| 29.09 | 46 855 | в 01:30 проект встал |
| 30.09-04.10 | 21 418 - 22 736 | полка под 402 |
| 05.10 (1-й час) | 1 085 | та же полка |

17 280 тиков в сутки (раз в 5 с). 150 000 / 17 280 = **~8,7 запроса на тик**
в здоровом состоянии.

## Что из этих 8,7 нужно ей, а что нет — прочитано по коду, а не на глаз

Три подпрограммы повёрнуты к заказчице, и у каждой на тихом ходу **ровно один**
запрос, после чего ранний выход:

- `разбудитьЕслиЖдут` (863) — будильник заданий. Один `select` из
  `claude_tasks?status=eq.new&limit=1`, пусто — выход на строке 874.
- `подтвердитьДоделки` (723) — то самое «принял» на замечание. Один `select`,
  пусто — выход на 746.
- `присланныеБоту` (1139) — ролики из бота. Один `select`, пусто — выход на 1158.
  Горячего цикла здесь нет: замеренные без заголовка отфильтрованы на 1165-1167
  и не качаются повторно (проверено — из 15 карточек `new` десять без
  `polished_at`, и все они уходят в этот фильтр).

Итого её часть — **3 запроса на тик**. Остальные **~5,7** это конвейер:
`двигатьПолосу` (334), `полосаПоЗаданиям` (964), `заказатьОписания` (1064),
`перевеситьТитры` (1296). Пятисекундной свежести конвейеру не нужно ни в одной
строке.

## Почему «поднять POLL_MS до 60000» — слишком грубо

Это запись из памяти, и она режет расход в 12 раз (до ~12 500 в сутки), но
вместе с конвейером замедляет и будильник: её задание с телефона будет ждать
подъёма Claude до минуты вместо пяти секунд. Промт пишется одну-две минуты,
то есть ожидание вырастает заметно — а экономии ради этого не требуется.

## Мера: две дорожки вместо одной

Быструю оставить на 5 с, конвейер увести на 60 с.

```js
// было (строки 1356-1369 — один тик на всё)
await подтвердитьДоделки();
await заказатьОписания();
await полосаПоЗаданиям();
await двигатьПолосу();
await разбудитьЕслиЖдут();
await просмотр(readyDir, false);
await просмотр(dubDir, true);
await просмотр(noSubsDir, false);
await перевеситьТитры();
await собратьТегиТиктока();
await присланныеБоту();
```

Стало — тик принимает признак дорожки:

```js
const POLL_MS = 5000;            // быстрая дорожка, как было
const МЕДЛЕННО_КАЖДЫЙ = 12;      // 12 x 5 с = 60 с

let номерТика = 0;

async function tick() {
  if (занят) { /* сторож без изменений, строки 1347-1353 */ }
  занят = true;
  началТик = Date.now();
  const медленная = (номерТика++ % МЕДЛЕННО_КАЖДЫЙ) === 0;
  try {
    // быстрая дорожка — всё, что заказчица чувствует сразу
    await подтвердитьДоделки();
    await разбудитьЕслиЖдут();
    await присланныеБоту();
    if (!медленная) return;
    // медленная дорожка — конвейер, раз в минуту
    await заказатьОписания();
    await полосаПоЗаданиям();
    await двигатьПолосу();
    await просмотр(readyDir, false);
    await просмотр(dubDir, true);
    await просмотр(noSubsDir, false);
    await перевеситьТитры();
    await собратьТегиТиктока();
  } finally {
    занят = false;
  }
}
```

`return` внутри `try` отпускает замок через `finally` — это проверено по
устройству сторожа (строки 1370-1372), замок не залипнет.

## Что это даёт

| вариант | запросов в сутки | чего ждёт заказчица |
|---|---|---|
| как сейчас | ~150 000 | 5 с |
| POLL_MS=60000 (запись памяти) | ~12 500 | до 60 с |
| **две дорожки** | 17 280 x 3 + 1 440 x 5,7 = **~60 000** | **5 с, без изменений** |

Сокращение в 2,5 раза и ни одной секунды её ожидания. Если понадобится больше,
следующий шаг — увести `подтвердитьДоделки` и `присланныеБоту` в медленную
дорожку тоже (останется ~28 000 в сутки), но тогда «принял» на замечание
приходит до минуты, а это она чувствует.

## Чего эта мера НЕ лечит — чтобы не было ложной надежды

Переход на Pro нужен всё равно и независимо: хранилище занимает 3 821 МБ при
бесплатном лимите 1 024, опросом это не чинится. Мера не снимает 402 и не
ускоряет разблокировку ни на минуту — она о том, чтобы после оплаты расход не
уехал обратно на 150 000 запросов в сутки за её деньги.

Оценка в гигабайтах намеренно не приводится: счётчик управляющего API даёт
**запросы**, а не байты, а путь к байтам (`analytics/endpoints/metrics`) под 402
отбивается. Из косвенного счёта (5 ГБ бесплатного егресса кончились примерно за
305 000 запросов) выходит около 16 КБ на запрос, то есть ~2,4 ГБ в сутки и ~72 ГБ
в месяц против 250 ГБ, включённых в Pro. Это **оценка, а не замер**: цифра 5 ГБ
взята из описания бесплатного тарифа, а не измерена. Вывод от неё не зависит —
полка в 150 000 запросов измерена прямо.

## Откат

Мера обратима целиком: вернуть строки 1356-1369 в прежний вид и убрать
`номерТика` с `МЕДЛЕННО_КАЖДЫЙ`. Ничего в базе не меняется, файлов не удаляется.
